# 個人字典 → 原生「建議聯絡人」

選取 **Zhuyin Personal Dictionary Candidates** patch，適用此專案的 Gboard 18.0.3。
本版直接將字典文字併入 `zh_tw_contacts_dict_3_3`，不是先前的使用者字典（kind 3）方案。

## 使用

1. 在 Gboard 原生設定開啟 **建議聯絡人**，並允許存取聯絡人。
2. Gboard → 補包設定 → 鍵盤配置 → **個人字典注音候選**，開啟補包開關。
3. 在個人字典新增「訂飲料」，語言選「所有語言」或中文，**捷徑留空即可**。
4. 儲存後會在背景讀取字典，並重建原生聯絡人建議列表。

字典新增、修改、刪除，以及切換補包開關，都會重建列表。
原有聯絡人會從原本的通訊錄來源重新匯入，字典詞條加入同一個 native 交易；
不建立手機聯絡人、不寫入系統 Contacts Provider。
本功能依賴原生「建議聯絡人」設定與聯絡人權限，沒有繞過它們。

補包設定會顯示中文詞條數與上次重建加入的建議詞數。
建議詞數可能包含原生姓名拆分後的詞（例如「訂飲料」及「飲料」），
與真聯絡人重複的詞不會再寫入，避免蓋掉原有權重。
如果一直顯示「等待聯絡人建議列表重建」，請確認原生設定與權限均已開啟。

## 實作

* 字典直接讀取 app 自己的 `PersonalDictionary.db`：`SELECT word, locale FROM entry`。
  不讀取捷徑欄位，不依賴捷徑匯入器，也不要求 Android 系統個人字典來源先匯入成功。
* `qci.dU()` 是個人字典儲存通知。hook 在原方法結束後排程背景快照與聯絡人重建，
  不等舊 `ShortcutsDataManager` 的延遲匯入。
* 每次變動遞增快照版本。`ndd.A()` 清掉原有通訊錄數量／時間快取後排程重建；
  在 `ndd.j(Cursor)` 中，若字典版本尚未套用，必須允許重建，避免相同聯絡人數被略過。
  此判斷位於原本的 Provider 查詢之後，沒有繞過聯絡人權限。
* `hbf.c()` 進入時取得原本的 contacts `hbi` transaction；使用 `fhi.a()` 的中文姓名拆分規則，
  將字典詞以 `nativeInsertOrUpdate(long,String,int,boolean)` 寫入同一個 kind 2 暫存字典。
* 原本的 `hbf.c()` 負責持久化及 `L(2)` 刷新。只有該流程成功後才標記字典版本已套用。
  匯入中止或持久化失敗會保留待重建狀態；舊版本完成時也不會蓋掉較新字典的待更新狀態。
* 每次聯絡人重建還會重新讀取個人字典，避免重啟後載入舊快照。
* 舊原型的 kind 3 ownership 記錄若存在，僅清除當時由原型新增的詞；既有學習詞不清空。

原生聯絡人解碼器負責讀音、簡拼、候選排序和提交；不額外附帶 ICU 注音表，也不自行插入候選。
實際支援的讀音、聲調省略及排名以裝置上的 Gboard 原生模型為準。
目前僅納入中文／所有語言的純漢字詞條，不要求捷徑，也不讀取捷徑的內容。

## 驗證與封裝

測試使用 SQLite 個人字典與原生交易契約 fixture，涵蓋空捷徑、變更通知、快取失效、
新增／修改／刪除重建、開關、真聯絡人保留、失敗與中止、較新版本的更新、舊版遷移與設定計數。
原始 APK 的 patch 測試驗證 `qci.dU`、`hbf.c/b`、`ndd.j` 的冪等注入與 dex round trip。
這些測試不等於裝置上的 native 解碼實測；沒有操作手機輸入或讀取通訊錄。

使用 `:patches:buildAndroid` 建置，檢查 mpp 根目錄 `classes.dex` 後交付。
3.15.0 正式版檔案為 `patches-3.15.0.mpp`。
